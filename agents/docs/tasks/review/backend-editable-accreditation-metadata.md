# Editable Accreditation Metadata + First-Accreditation Tenure Anchor

**Owner:** backend
**Created:** 2026-06-14

Make accreditation metadata (`name`/`institution`/`field`) editable post-accreditation by re-broadcasting an admin-signed `accredit` op carrying merged values, and introduce a first-accreditation tenure anchor so the displayed "accredited since" derives from the EARLIEST accredit op (all-history, across sanction gaps) rather than the latest op.

## Why

Today accreditation metadata is one-shot. The `accreditation.verify` existing-accreditation gate in `routes/accreditation.ts` (the `findExistingAccreditation` short-circuit) returns the prior `tx_id` WITHOUT re-broadcasting, so any new metadata captured at a second `/request → /verify` is silently discarded. The in-code docblock there explicitly flags that an updateable-metadata flow needs a paired design pass. ORCID-accredited accounts grant with empty `institution`/`field` (see `broadcastWotAccreditation` for the analogous WoT empty-field case) and have no path to fill them in.

Separately, every tenure-display consumer reads the LATEST accredit op's `event_timestamp` (the payload `timestamp` field). Once metadata edits re-broadcast a fresh accredit op, that payload timestamp is rewritten, so "accredited since" would jump to the edit time. The displayed tenure must anchor on the EARLIEST accredit op's CHAIN BLOCK TIME (not the payload `timestamp`, which a re-broadcast rewrites), counting all history across sanction gaps. Metadata reads stay on the latest op.

This is the canonical reference already written into `agents/docs/ARCHITECTURE.md` § 2 ("Accreditation Lifecycle & Sanctions") and the per-op fresh-auth requirement in § 6.4 / invariant #1 in § 6.5 — read those before implementing.

**1. [P2 — residual edge of round-1 item 3] The "HAF confirmed reachable after the op-read" inference is fragile; a HAF blip after `getLatestAccreditOp` succeeds returns a misleading 403 instead of a retriable 503.**
The item-3 design uses `getLatestAccreditOp` as an upstream HAF-reachability gate (throw -> 503) so the downstream `getAccreditedSet` / `hasUnliftedSanction` 403s are "trusted as genuine."
