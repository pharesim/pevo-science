## PINNER-CONTENT-HASH-VERIFY-ON-PIN (archived 2026-05-21) — superseded by pinner-embedded-ipfs-node-via-boxo ✗

Commit `28167cb6` wrapped `EmbeddedNode.Pin`'s `io.Copy` in a `TeeReader` to the multihash function declared by the CID, then byte-compared the hasher result to the CID's multihash digest. PEvO's own upload path (`backend/src/routes/ipfs.ts:98` `POST /api/v0/add?pin=true`) uses Kubo defaults (CIDv0/dag-pb, no raw-leaves, default chunker), so 100% of PEvO-uploaded papers fail the verify too. The structural fix is not "patch the verify" but "replace EmbeddedNode's HTTP-cache architecture with a real in-process IPFS node via `github.com/ipfs/boxo`" — the original design intent (pinner ships as a single Go binary that embeds the IPFS node, one file to run for third-party libraries helping share PEvO content). New task filed: `pinner-embedded-ipfs-node-via-boxo.md`.
