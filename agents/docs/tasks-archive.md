## ARCHITECT-HAF-UNAVAILABILITY-VOUCHED-SET-POLICY (archived 2026-05-06) — fail-closed with surgical minimization

P1 architect-design task. Decided fail-open vs fail-closed for the consent-ops admit gate when HAF is unavailable. Resolution: **fail-closed**, matching PEvO's existing security-critical HAF-required reads (`backend/src/routes/orcid.ts:1502-1506` "Fail closed when HAF is unavailable: returning null would silently bypass...", `backend/src/routes/claims.ts:35,75`) and the discriminated-union return shape from `backend/src/routes/bridge.ts:161-177`.

**Decision shape:**
- `fetchConsentOpsForPaper` returns `{status: 'ok', ops}` | `{status: 'haf_unavailable', reason: 'no_pool' | 'query_failed'}`. `getVouchedAuthors` propagates the same union upward. The pure `computeVouchedAuthors` is unchanged. Filed as a [TODO Backend] block in `backend-coauthor-trust-model.md` Round 1 follow-up section so the round-1 implementer lands the signature change before Round 2 picks up.
- Round 2 integration site in `papers.ts` short-circuits the HAF fetch when the consent flow is inert: single-author claimed-set (root broadcaster implicit-vouched per ARCH.md rule 1) and bridge papers (per ARCH.md "Bridge papers" subsection). Multi-author chains call `getVouchedAuthors`; on `'haf_unavailable'` the route returns 503 INTERNAL_ERROR via `sendError`. Same posture applies to `/api/me/authorships/pending` (sibling task `backend-notification-infra-for-consent-ops`).
- Operator signal: per-request structured pino log on every fail-closed firing (event name unchanged from Round 1's `consent_ops.fetch_failed` OR renamed to `consent_ops.haf_unavailable` — implementer's call, one stable name on both `no_pool` and `query_failed` branches). Sampling is the log pipeline's job, not the code's.

**Why fail-closed:** the alternative (fail-open / degrade to root-only) would silently demote legitimate co-author continuations BELOW the cumulative-union claimed-set baseline currently in production AND create an attacker-attractive bypass window during HAF flaps. The "chain is SSoT" stance settled in `feedback_dont_relitigate_settled_ssot` is binding here: if we can't read the chain, we don't answer the security question. Single-author papers (overwhelming majority in beta) and bridge papers don't hit the HAF fetch at all under the surgical-minimization integration shape, so the fail-closed surface is bounded to genuinely multi-author papers — small in the beta cohort.
